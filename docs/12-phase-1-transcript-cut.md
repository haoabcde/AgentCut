# 第一阶段：可信口播文字剪辑

## 1. 阶段目标

第一阶段只完成一个可交付结果：用户导入一段 5–15 分钟中文口播，系统生成与原片对齐的文字稿，Agent 给出删除方案，用户通过文字审阅、试听、接受或恢复，最终导出一版可继续使用的初剪。

核心判断不是“AI 能否找到一些口头禅”，而是用户是否敢让 Agent 真正删除原片内容。

截至 2026-08-13，真实 ASR、候选审阅 UI、人工连续文字删除、剪后 Viewer、提交前删除效果试听和持久化 MP4/SRT 导出链路均已进入可执行实现；真实素材已通过新入口完成建项和幂等续跑。完整阶段仍需真实操作者完成全部内容取舍、成片导出与 cut 边界听审 Gate，不把“代码已接通”写成“质量已通过”。

## 2. 参考与取舍

公开的剪映智能剪口播资料显示，其核心交互包括：

- 文字与播放位置联动。
- 将停顿、语气词和重复分组计数、筛选。
- 在文稿中用色块标记建议删除范围。
- 支持单项删除、取消标记和批量删除标记项。

参考来源：[剪映智能剪片图文流程（2024-03-05）](https://www.technice.com.tw/opinion/98506/)。这是旧版本的公开二手资料，只用于确认基本交互，不代表剪映当前完整实现。

AgentCut 借鉴“文字即剪辑入口”，但不照搬黑箱批量删除：候选、已提交删除、风险、锁和恢复必须是不同状态；高风险内容不得进入无差别批量操作。

另一个工程参考是 [Agentchengfeng/chengfeng-videocut-skills](https://github.com/Agentchengfeng/chengfeng-videocut-skills)。AgentCut 采用其中经过源码确认的部分：

- Transcript token 必须有跨重排稳定的 `wordId`，删除方案引用 word ID 集合并附带 source range，不能依赖行号或数组位置。
- Agent/Skill 只生成语义候选和 proposal；project store/runtime 是 revision、Cuts、媒体操作和审计的唯一写入者。
- 审阅页面只在 transcript 与 proposal 已准备完成后进入，不能用空工作台或假数据代替任务进度。
- 用户确认后再次读取 project/proposal revision；任一 revision 漂移都返回审阅，而不是继续执行旧确认。
- 剪后字幕必须做边界 QA；是否全量重新 ASR 由 benchmark 决定，不能仅机械拼接后直接宣称字幕完成。

不直接复用该仓库的两态删除模型或独立 Runtime：第一阶段需要同时表达 `proposed_remove` 与 committed deletion，且 AgentCut 的源素材始终不可变，所谓“应用剪切”只提交非破坏 Timeline transaction，MP4 是派生输出。

## 3. 核心界面

桌面宽屏采用双栏：

- 左侧为视频预览、播放控制和简化音频波形。
- 右侧为口播文稿、候选统计、筛选和批量操作。
- 不在第一阶段实现完整多轨时间线；只保留能说明 cut 边界和播放位置的紧凑时间带。

文稿顶部固定显示：

- 当前 revision 与分析状态。
- `停顿`、`语气词`、`重复/重说`、`说错纠正`数量；语义类别不得为了展示方便被合并成另一种理由。
- 建议删除总时长、低/中/高风险分布。
- `应用低风险项`与`逐项审阅`；不提供包含高风险项的“一键全部删除”。

## 4. 文字状态

| 状态 | 视觉表达 | 点击行为 | 是否影响时间线 |
|---|---|---|---|
| 正常文字 | 默认正文 | 跳转并播放对应原片 | 否 |
| Agent 候选删除 | 浅色背景 + 原因短标签；不加删除线 | 展开理由、风险、置信度和试听 | 否 |
| 当前选中 | 清晰描边或选区底色 | 循环播放前后文 | 否 |
| 已提交删除 | 低对比度文字 + 删除线，仍占据文稿位置 | 试听原始范围、查看 transaction、恢复 | 是 |
| 用户拒绝/保留 | 短暂保留标记；后续显示为普通文字并记录决定 | 可重新评估 | 否 |
| 用户锁定 | 锁图标 + 不依赖颜色的边界标识 | 查看锁范围/原因 | 阻止 Agent 修改 |

删除线只代表已经进入 committed revision 的删除。若 Agent 只是提出建议，必须仍显示为候选，防止用户误以为项目已被修改。

## 5. 核心交互

1. 点击文字：播放头跳到对应 source range；已删除文字默认试听原片而非剪后结果。
2. 连续选择文字：用户点击普通文字起点、Shift 点击终点形成稳定 word range；范围不得包含待审、已删除、已锁定文字，也不得跨过这些状态的 gap。合法范围可先基于只读虚拟 Timeline 试听“删除选中文字”的拼接效果，再显式提交或取消；选择预览不得创建人工 CandidateSet、Proposal 或 Timeline transaction。
3. 点击候选：显示删除原因、证据范围和预计缩短时长；重复、重说和说错纠正必须单列结构化“对照保留段”，展示保留文字并可单独试听。历史候选若创建时没有保存该结构，必须显示“历史证据缺失”而不是从说明文字推测范围。用户还可循环试听待删原片上下文，或基于当前 revision 的只读虚拟 Timeline 试听“若删除此段”的真实硬切效果。删除效果试听不得创建 transaction、推进 revision 或自行在前端重算剪辑片段。
4. 应用建议：先生成 revision-bound proposal，展示项目时长变化，再以一个原子 transaction 提交。
5. 恢复删除：生成 inverse transaction，不改写历史 revision；恢复后 Agent 必须读取最新 revision。
6. 编辑错字：只修改 Transcript/Caption 文本，不得静默改变媒体删除范围。

所有选择以稳定 `wordId` 为主要身份，以精确 source range 为媒体证据。ASR 纠错可以更新显示文字，但不能使已经审阅的删除对象漂移到另一个词。

## 6. Agent 原生差异

相比传统文字剪辑，AgentCut 必须多提供四件事：

- 为什么删：保留原始语义类别的 `reasonCodes`、统一中文标签、中文解释和证据范围；正文、队列、检查器与时间线不得直接暴露内部英文码。
- 有多危险：风险等级与校准后的置信度。
- 谁做的：Agent、用户、workflow、模型和 source revision。
- 如何回来：inverse、版本、锁和重启后一致恢复。

因此 UI 不是 ASR 文本编辑器的外壳，而是 command/revision 系统的可视化审阅器。

## 7. 第一阶段明确不做

- 完整多轨时间线、关键帧和特效面板。
- 访谈、多说话人和多机位。
- StyleSpec、B-roll、AI 生成素材和复杂包装。
- 多个 ASR Provider 同时产品化；先通过 benchmark 选择一条默认路径。
- 高风险内容的无确认批量删除。

## 8. 退出 Gate

- 5 条真实中文口播均能完成导入、转写、方案审阅、应用、恢复和 MP4 导出。
- 任何删除都能从删除线定位到 source range、reason、actor 和 transaction。
- 高风险自动删除为 0；`definite_remove` precision 目标不低于 98%。
- 至少 95% 的 cut 边界无吞字或截断音节。
- 刷新、重启、重复请求和 revision conflict 不改变已经审阅的结果。
- 用户手工恢复或锁定后，后续 Agent 不得再次覆盖该决定。
